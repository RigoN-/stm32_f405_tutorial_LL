1. Архитектура и Управление путями 
(BUILD_MODE, VPATH)BUILD_MODE ?= DEBUG: 
Переменная по умолчанию определяет стратегию оптимизации и генерации отладочных символов. Использование условного оператора ?= позволяет переопределять режим прямо из командной строки (например, make BUILD_MODE=RELEASE).
OUTPATH: Изолирует весь мусор компиляции в отдельные директории (./_build/debug/ или ./_build/release/). Это предотвращает смешивание бинарных файлов разных режимов.OBJS: Динамически собирает список объектных файлов. Функция $(notdir ...) убирает длинные относительные пути к исходникам (например, превращает ../../driver/core/main.c в main.c), а $(addprefix ...) принудительно перенаправляет их создание в $(OUTPATH).
VPATH: Специальная переменная GNU Make. Она содержит уникальный список всех папок с исходным кодом. Благодаря этому, когда make ищет файл main.c для создания _build/debug/main.o, она автоматически сканирует пути из VPATH.
2. Аппаратные параметры MCU (MCUFLAGS)
-mcpu=cortex-m4: Указывает компилятору использовать набор инструкций (ARMv7E-M), специфичный для процессорного ядра Cortex-M4.
-mtune=cortex-m4: Оптимизирует планирование инструкций под конвейер конкретно этого ядра.
-mfpu=fpv4-sp-d16: Включает поддержку аппаратного блока вычислений с плавающей точкой (FPU) версии VFPv4 в режиме одинарной точности (Single Precision) с 16 шестнадцатеричными регистрами (именно такой блок установлен в STM32F405).
-mfloat-abi=hard: Предписывает использовать аппаратные регистры FPU для передачи аргументов с плавающей точкой при вызовах функций. Это радикально ускоряет математику (в отличие от soft или softfp).-
mthumb: Переводит процессор в режим выполнения компактного 16/32-битного набора инструкций Thumb-2 (стандарт для микроконтроллеров ARM Cortex-M).
3. Опции компилятора (CFLAGS)
-Wall -Wextra --pedantic: Набор флагов, включающий максимальный уровень предупреждений компилятора о потенциальных ошибках, стилистических несоответствиях стандартам Си и сомнительных конструкциях.
-Wno-unused-parameter: Подавляет варнинги о неиспользуемых аргументах внутри функций. Это крайне удобно при написании системных заглушек и callback-интерфейсов, где некоторые параметры требуются стандартом, но не используются физически.
-MMD -MP: Флаги автоматической генерации зависимостей. Компилятор создает для каждого .c файла сопутствующий .d файл, где записано, от каких .h заголовков он зависит. Если вы меняете только .h файл, make благодаря этому перекомпилирует только связанные модули без необходимости делать полный clean.
4. Различия режимов оптимизации
DEBUG:-O0: 
Полное отключение оптимизации. Код собирается строго строка в строку, переменные не кешируются в регистры процессора. Это предотвращает баги асинхронного изменения памяти в прерываниях (хотя для полной надежности ключевое слово volatile для глобальных общих переменных остается обязательным).
-g3 -gdwarf-2: Генерация расширенной отладочной информации в стандарте DWARF-2 для пошаговой отладки в GDB.
RELEASE: -Os: Оптимизация размера результирующего бинарного файла. Идеально для встраиваемых систем с ограниченной Flash-памятью.
-flto: Link Time Optimization (Оптимизация на этапе линковки). Компилятор анализирует проект целиком, а не пофайлово. Это позволяет ему автоматически удалять неиспользуемые библиотечные функции и инлайнить мелкий код из разных модулей.-fdata-sections -ffunction-sections: Упаковывает каждую переменную и каждую функцию в свою индивидуальную секцию в объектном файле. Работает в связке с линкером.
-fsingle-precision-constant: Принудительно интерпретирует константы с плавающей точкой (например, 3.14) как float, а не double, избавляя Cortex-M4 от тяжелых программных вычислений двойной точности.-fno-math-errno -ffast-math: Отключает выставление системной переменной errno для математических функций и включает агрессивные оптимизации расчетов, жертвуя строгими стандартами IEEE ради скорости выполнения.
5. Опции линкера (LDFLAGS)-static: 
Запрещает использование динамических библиотек.-
-specs=nano.specs: Подключает оптимизированную по размеру и потреблению памяти компактную стандартную библиотеку Си (Newlib-nano) вместо стандартной тяжелой glibc.
--specs=nosys.specs: Подключает пустые системные заглушки по умолчанию. Благодаря доработке с файлом syscalls.c и __attribute__((weak)), линкер бесшовно заменяет пустые заглушки на наши функции работы с UART, не вызывая предупреждений.
-Wl,-Map=...: Предписывает линкеру сгенерировать подробный .map файл карты памяти, где расписан каждый байт проекта.
-Wl,--gc-sections: Garbage Collection секций. В связке с -fdata-sections/-ffunction-sections этот флаг на этапе линковки полностью вырезает из финальной Flash-памяти все функции, которые ни разу не вызывались в коде.
